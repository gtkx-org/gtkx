`gtkx upgrade` moves every GTKX package to one release. It rewrites each `@gtkx/*` and `create-gtkx` spec in the project, or in every member of its npm, pnpm or Yarn workspace, and the entries of pnpm catalogs, keeping each spec's range operator. `peerDependencies` ranges move only when they do not accept the new version, so deliberately wide ranges stay as written. It then installs with the project's package manager and deduplicates, and fails naming any GTKX package the install left on another version, for example through a Yarn catalog, overrides or a range that accepts a newer release, and any GTKX peer range that still excludes it. Without an argument it picks the newest release on the dist-tag the project already follows, such as `beta`; `gtkx upgrade 2.0.1` or `gtkx upgrade latest` picks one. Bumping versions by hand used to leave undeclared packages such as `@gtkx/codegen` or `@gtkx/native` behind until a separate dedupe, and missed catalog entries that `pnpm update` overwrites.
